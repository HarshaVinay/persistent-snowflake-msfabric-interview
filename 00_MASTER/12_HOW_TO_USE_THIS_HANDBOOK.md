# How To Use This Handbook

## The learning loop
For every topic:

1. **Understand** — simple explanation.
2. **Mental model** — architecture/flow.
3. **Syntax** — code or commands where applicable.
4. **Example** — small realistic dataset.
5. **Interview answer** — 30–60 seconds.
6. **Follow-up** — likely interviewer probes.
7. **Scenario** — failure/performance/security problem.
8. **Project connection** — Disaster or Cricket project.
9. **Self-test** — answer without notes.

## Evidence discipline
A/B questions are historical interview evidence. C questions are predictions. D questions are generic preparation. Never say “Persistent asks this” for C/D.

## Answer discipline
When discussing your own projects, separate:
- **Implemented:** you actually built/tested it.
- **Studied:** covered in training but not personally implemented.
- **Proposed:** a production redesign you would implement.

## Final interview response pattern
**Direct answer → reason → example → trade-off.**

For architecture:
**requirements → scale/SLA → source → ingestion → storage → transformation → serving → quality → security → monitoring → cost.**

## Revision modes
- **Learn mode:** full explanations.
- **Drill mode:** questions only.
- **Interview mode:** spoken answers + follow-ups.
- **Coding mode:** timed problems.
- **Final mode:** random mixed interview.
